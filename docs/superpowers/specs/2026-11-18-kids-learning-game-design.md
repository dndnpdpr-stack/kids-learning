# 유아 학습 게임 (한글·숫자·ABC) 설계

작성일: 2026-11-18

## 1. 목적과 배경

- 4~5세 아이가 놀면서 **한글, 숫자, 알파벳**을 익히는 게임이다.
- 1차 사용자는 요청자 본인의 아이다. 나중에 **앱스토어(iOS/Android) 배포**를 고려해서 처음부터 그 기준에 맞춰 만든다.
- **모바일 앱과 일반 웹 브라우저** 양쪽에서 모두 동작해야 한다.
- 아이의 현재 수준:
  - 숫자: 어느 정도 읽고 셀 수 있다.
  - 한글: 처음 배운다.
  - 알파벳: 처음 배운다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 글을 못 읽는 아이가 **부모 도움 없이 혼자** 실행해서 놀 수 있다.
- 한글 자모와 알파벳 대문자를 보고 소리와 그림 단어를 연결할 수 있게 된다.
- 숫자는 20까지 세기, 많고 적음 비교, 그림으로 하는 간단한 더하기까지 간다.

**비목표 (첫 버전)**
- 계정, 로그인, 기기 간 진도 동기화
- 결제와 광고
- 소문자, 받침 있는 글자, 단어 읽기 (이후 버전에서 다룸)

**실패 조건 (동작은 해도 실패로 보는 경우)**
- 아이가 글자 안내를 읽어야만 진행할 수 있다.
- 틀렸을 때 혼나는 느낌을 준다 (큰 X 표시, 경고음, 감점).
- 아이가 실수로 외부 링크, 설정, 결제 화면으로 빠져나간다.
- 외부로 데이터가 전송되어 스토어의 아동 정책(Apple Kids Category, Google Families)을 위반한다.

## 3. 제약

- 한 코드로 웹과 앱을 함께 지원한다.
- 아이 손가락에 맞게 터치 영역을 크게 만든다 (최소 약 64px). 휴대폰과 태블릿 모두 지원한다.
- 데이터 수집을 하지 않는다. 외부 분석 SDK도 넣지 않는다. 진도는 기기 안(localStorage)에만 저장한다.
- 첫 실행 이후에는 오프라인에서도 동작한다.

## 4. 검토한 방법 (Approaches)

| 방법 | 장점 | 단점 |
|---|---|---|
| **① 웹앱(HTML/JS) + Capacitor로 앱 포장** ✅ 선택 | 코드 하나, 가장 빠른 개발과 수정, 브라우저에서 바로 실행 | 고사양 3D에는 부적합 (이 게임엔 불필요) |
| ② Flutter | 앱이 매끄러움 | 웹 로딩이 무겁고, 수정할 때마다 빌드가 필요해 느림 |
| ③ React Native (Expo) | 앱 품질 좋음 | 웹 지원이 덜 자연스럽고, 게임형 화면에 손이 많이 감 |

**선택: ①** — 요청자가 결정. 이 게임에 필요한 건 터치, 소리, 간단한 애니메이션 정도라서 웹 기술로 충분하다. 아이에게 먼저 써 보게 하고 바로 고치는 과정을 빠르게 반복하는 데 가장 유리하다.

## 5. 결정된 내용

### 5.1 구조
- 첫 화면에 **세 개의 세계**가 있다: 🐻 한글, 🐰 숫자, 🦊 ABC.
- 화면 위쪽에 별 개수를 표시하고, 구석에 잠긴 부모 메뉴 버튼을 둔다.

```
┌─────────────────────────┐
│   ⭐ 12      [부모 🔒]   │
│   🐻 한글   🐰 숫자     │
│        🦊 ABC           │
└─────────────────────────┘
```

### 5.2 세계마다 같은 3단계
1. **만나기**: 글자를 누르면 이름, 소리, 그림 단어가 나온다 (예: ㄱ → "기역, 기차!").
2. **찾기**: 음성으로 낸 문제("ㄴ을 찾아봐!")를 듣고 2~3개 보기 중에서 고른다.
3. **따라 쓰기**: 손가락으로 글자 획을 따라 그린다.

### 5.3 세계별 내용
- **한글**: 자모를 그림 단어와 함께 배운다 (추천안 채택). 기본 자음 14개와 기본 모음 10개를 배운 뒤 "ㄱ+ㅏ=가" 조합 단계로 간다.
- **숫자**: 1~10은 빠르게 확인만 한다. 그다음 순서는 사물 세기(20까지), 많고 적음 비교, 그림으로 하는 더하기다.
- **ABC**: 대문자 26개, 각 글자의 이름과 소리, 그림 단어 (A → apple 🍎).

### 5.4 공통 원칙
- 모든 안내는 **음성**으로 한다. 글자 안내에 의존하지 않는다.
- 틀리면 "다시 들어볼까?"처럼 부드럽게 다시 시도하게 한다. 맞히면 별을 주고 짧은 축하 애니메이션을 보여 준다.
- 광고, 로그인, 외부 링크를 넣지 않는다.
- 부모 메뉴는 잠가 둔다.

## 6. 구현자 판단으로 정한 사항 (요청자 확인 필요 시 변경)

- **기술 스택**: Vite + TypeScript, 프레임워크 없이 가볍게 만든다 (UI 컴포넌트 수가 적음). PWA로 오프라인을 지원하고, Capacitor로 iOS/Android 빌드를 만든다.
- **음성**: 1차로 Web Speech API(TTS, ko-KR / en-US)를 쓴다. 음성 재생은 `speak(key)` 하나로 추상화해서 나중에 녹음 파일(mp3)로 교체할 수 있게 한다. 기기에 한국어 음성이 없으면 녹음 파일이 필요하므로 위험 요소로 기록해 둔다.
- **그림**: 첫 버전은 이모지와 간단한 SVG를 쓴다. 스토어에 배포하기 전에 일러스트로 교체할 수 있도록 데이터와 그림을 분리해 둔다.
- **화면 방향**: 세로와 가로 모두 지원한다. 레이아웃은 화면 크기에 맞춰 늘어나고 줄어든다.
- **부모 잠금**: 버튼을 3초 동안 길게 눌러야 열린다. 부모 메뉴에서는 진도 초기화, 소리 크기, 세계별 진도를 확인할 수 있다.
- **진행 방식**: 세계 안의 글자 묶음(예: ㄱ~ㅁ)마다 만나기 → 찾기 → 따라 쓰기를 진행한다. 찾기를 3번 맞히면 다음 묶음이 열린다. 이미 열린 묶음은 언제든 다시 할 수 있다.
- **따라 쓰기 판정**: 획 경로 위에 놓인 체크포인트를 순서대로 지나가면 통과로 본다. 판정은 관대하게 한다.
- **한 판 길이**: 한 활동이 1~3분 안에 끝나도록 짧게 구성한다.

## 7. 구현자에게 맡기는 부분

- 세부 애니메이션, 색상, 효과음
- 그림 단어 목록 (아이에게 익숙한 단어로 고름)
- 폴더 구조, 테스트 구성
